# 基础字段、页面时间与历史数据升级

本文记录 2026 年 9 月 15 日实施的质量规则升级。软件验证、历史数据重算和新的实机采集验收分开记录。

## 现在怎样计数

标题、作者和正文均已读取，就计入“基础字段可读”。保留由页面明确证据确认“未展示标题”的例外。正文是否完整交给人工核对，程序不再依据控件是否落在一屏内、是否存在省略号等条件断言正文不完整。

“已保存记录”“基础字段可读”“可靠 ID 去重数量”和“人工确认数量”含义不同：没有可靠笔记 ID 的观察仍保存、仍可计入可读目标，但可能与其他观察重复。历史记录不会根据标题或正文相似度合并，也不会补造 ID。

原文没有被改写。缺失字段保留为空并说明原因；普通省略号与连续句点不单独构成读取失败。确实存在替换乱码或字段未读到时仍明确标注。

## 时间与平台话题

时间显示和导出均保留页面原文，例如“昨天上午11:10广东”，不推算日期、年份或时区。“编辑于”开头的显示归为“编辑时间”，不能作为首次发布时间。

平台话题必须来自已经校准、有证据支持的话题组件或行为。普通正文 `#词组` 不被转换为平台话题。无法确认时显示“平台话题未能识别”；这不表示该帖没有标签。

补读字段附带对应截图和 UI 树的证据引用。不同截图中的信息只在同一次、已经关联到该观察的详情访问内组合；有冲突或证据损坏时不补填。

## 已有数据的处理结果

2026 年 9 月 15 日的历史数据检查得到：

| 项目 | 升级前 | 升级后 |
|---|---:|---:|
| 已保存观察记录 | 103 | 103 |
| 基础字段可读计数 | 48（旧完整性门槛） | 99 |
| 可读取页面时间 | 4 | 98 |
| 可靠笔记 ID | 0 | 0 |
| 已确认平台话题 | 0 | 0 |

98 条时间中，59 条为页面普通时间显示，39 条明确带“编辑于”。剩余 4 条未计为基础字段可读的记录均未读到标题和正文，继续保留原始记录及原因。

这些数字来自已经保存的真实页面证据的重新评估，不是新增采集，也不是 99 篇不同笔记的验收结论。

处理前已备份数据库。原来的质量判断及计数保存在 `quality_assessment_audits`；原文、截图、UI 树、笔记身份、任务状态、目标和已用预算的前后比较全部通过。第二次预览显示需要变更的观察和任务均为 0。

任务重算后即使已经达到目标，也不会自动开始。用户下一次明确继续时，执行程序依据新的计数正常收尾。

## 导出及兼容字段

新的 JSONL 和 CSV 均从数据库读取。旧导出文件保留，重新导出生成新文件。

| 字段 | 含义 |
|---|---|
| `eligible` / CSV `base_readable` | 基础字段可读，兼容保留旧布尔字段名称 |
| `quality_revision = 2` | 本次质量规则 |
| `body_complete = null` | 不再自动判断；不能理解为“确认不完整” |
| `completeness_status = not_assessed` | 完整性等待人工核对 |
| `fields.published_at.raw` | 页面原始时间文字 |
| `time_kind` | `published`、`edited` 或 `not_readable`；不是转换后的日期 |
| `topics_status` / `topics` | 话题确认状态及已确认列表 |
| `topic_sources` | 各平台话题的读取方式与证据引用 |
| `identity_status` | `verified` 或 `unverified`，独立于字段可读状态 |
| `fields.*.evidence_ref` | 对应字段的证据清单路径 |

记录格式版本提升至 2，人工验收入口兼容版本 1、2；人工确认和来源证据校验仍然必须通过。CSV 为避免表格公式执行会对部分展示单元格加前导单引号，`record_json` 和 JSONL 保留数据库原值。完整证据信息较长，Python 读取 CSV 做无损比较时需要提高 `csv.field_size_limit`。

本次导出位于 `var/quality-upgrade/exports/20260915T131414.194656Z/`。其中 `verification.json` 记录了数据库、JSONL、CSV 内 `record_json` 全量相等及计数一致的检查结果。任务和原文保留检查见 `var/quality-upgrade/preservation-check.json`。

## 维护及验证

`reassess_history(engine, profile=profile, evidence_root=path)` 默认只预览，不写入数据库、不连接手机。正式应用须先完成数据库备份，停止采集，再显式设置 `dry_run=False`。更改与审计记录在同一事务内提交；仍有运行中任务时拒绝应用。

历史 XML 必须按原始字节解码，不能转换 CRLF 换行，否则已有文字补充证据的哈希校验会失效。已经验证的原文与 uiautomator 的表情序列化形式，仅用于同次访问内的一致性核对，不用于推断身份或重建未知原文。

本模块验证：124 项质量、解析、导出、历史事务和人工验收测试通过；12 项隔离 PostgreSQL 测试通过，覆盖迁移前后数据保留、升级、降级及模型一致性；相关 Ruff 检查通过。测试夹具均为 synthetic，不计入真实成果。新版本实机导航速度、暂停恢复和话题／笔记 ID 校准结果由主交付报告另列。
