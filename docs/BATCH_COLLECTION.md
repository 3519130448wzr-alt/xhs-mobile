# 单机批量采集

本说明适用于 **0.5.0**：每词默认 10 条、最大 500 条，同一台手机依次执行最多 20 个关键词。500 条状态机测试属于 synthetic 工程验证，不是 500 条真实采集成果。

2026-09-13，用户确认“香港城市大学”这轮采集成功并验收。该任务正常结束，数据库保存 62 条观察，其中 30 条满足程序的基础字段质量条件。本轮确认已作为任务级事件和基线报告留档，原始记录及证据保留。

持久多关键词批次支持：**一次填写多个关键词 → 同一台手机依次执行 → 自动保存 → 暂停后恢复原批次 → 统一导出。**

## 桌面操作

日常双击桌面 **小红书采集助手.app**，单关键词与多关键词使用同一表单：

1. 在“开始采集”逐行填写或粘贴关键词，重复项会提示并合并。
2. 填写每个关键词的目标条数，默认 **10**，范围 **1–500**，最多 **20** 个不同关键词；开始前可查看总目标。
3. 点击开始，程序检查数据库和手机后依次运行；在“任务与结果”查看当前关键词和每词进度。
4. 需要暂停时点击“暂停”，等待实际停止；下一次从同一批次点击继续。
5. 在批次详情预览、导出或打开结果文件夹；手机离线时也可查看与导出。查看历史不会自动导出，正常采集收尾会尝试自动导出。

旧终端菜单继续保留：**6** 新建批次、**7** 恢复、**8** 查看／导出，运行时用 **Ctrl+C** 请求暂停，见 [终端维护入口](ONE_CLICK.md)。

新建批次时，每个子任务按目标生成并保存独立预算：详情访问为 `max(100, 3 × 目标)`，列表滚动为 `max(50, 向上取整(详情预算 ÷ 2))`。每词目标 500 对应 **1,500 次详情／750 次列表滚动**。配置中的新任务硬上限为 1,500／750；历史任务继续使用原策略，不因升级、暂停或恢复重新计算预算。保持至少 3 秒主动操作间隔、限频冷却和连续 3 次无新增停止。

连接方式与批次无关：新版支持开放连接 `open` 与自动白名单 `prefix_list`。开放模式下不探测公网 IP、更新名单或访问 RAM／钥匙串，需先完成云端开放规则；旧配置默认使用白名单模式，详见 [连接设置](AUTO_CONNECTION.md)。

不要用新的批次代替恢复原批次。原批次会保留全部任务 ID、观察记录、累计详情/滚动/重试预算及冷却状态，已经结束的任务会跳过。

## 批次如何停止和恢复

| 情况 | 批次行为 |
| --- | --- |
| 当前关键词达到目标 | 保存任务结果，继续下一关键词。 |
| 当前关键词没有新增候选或自然用完详情/列表预算 | 保留部分成果，继续下一关键词；整批最终标为“部分完成”。 |
| 用户暂停、设备错误、未知页面、需要登录/验证或人工处理 | 停止推进后续关键词，保留原任务；处理后恢复同一批次。 |
| 频率限制 | 复用原有持久冷却；等待与复查期间不会开始其他关键词来绕过限制。 |
| 数据库或证据保存失败 | 停止操作并保留已提交检查点，不把未保存数据计为成功。 |
| 程序或主机中断 | 重开 App，从原批次继续，跳过已结束的子任务，从未完成任务重新搜索。 |
| 页面读取次数已用完 | 对原批次选择“检查并继续”，仅为首个待恢复子任务进行检查并补充读取尝试。 |
| 导出失败 | 采集记录仍在数据库；使用批次“重新导出”，无需重新采集。 |

原预算仍有余量时，单任务可按 CLI `resume --task ... --limit ...` 提高目标补采，目标不能超过原任务的详情预算，累计已用次数不清零。提高目标不会补充已耗尽的预算。批次“恢复”用于继续未结束任务，不会自动提高目标或重新采集已经结束的部分任务。

需要人工确认的阻塞，先在手机正常解决，再用原批次的 `batch resume --batch ... --acknowledge`。该显式确认只用于首个待恢复任务，后续关键词遇到的新限制仍需处理。

读取额度耗尽时，“检查并继续”持有设备锁并核验连接、自动化服务及当前页面；通过后为原任务追加 **3 次读取尝试**。相同请求幂等，不会重复加额度；累计失败次数与其他运行预算保持不变。普通刷新、重启或批次恢复不会自动补充。登录、验证码及未知页面仍需人工处理并核验，冷却未到期不能跳过，不会靠后续关键词替受限任务继续采集。

## 导出内容

```text
var/exports/batches/批次ID/导出时间/
    notes.csv
    notes.jsonl
    summary.json
```

两种数据格式来自同一次数据库查询，保留每条记录原本的任务 ID、字段质量、原始值和证据引用。`summary.json` 列出关键词、任务、各自目标及本次实际导出数量，并包含数据文件 SHA256。每次使用新目录，不覆盖旧导出。导出途中失败会留下 `INCOMPLETE.txt`；该目录不视为完整交付。

各关键词合格观察数相加不代表跨关键词不同笔记数。逐条身份核验、疑似重复处理及原计划的 3 个关键词各 10 篇验收继续使用原审阅与验收机制。

## 命令行

仍使用已有的本机数据库包装入口；以下实际关键词由实验室选择。

```sh
export XHS_ADB_SERIAL='127.0.0.1:6100'
.venv/bin/python scripts/local_postgres.py start
.venv/bin/python scripts/local_postgres.py migrate
.venv/bin/python scripts/local_postgres.py xhs -- batch run --device lab01 \
  --keyword '实际关键词甲' --keyword '实际关键词乙' --keyword '实际关键词丙' --limit 10
.venv/bin/python scripts/local_postgres.py xhs -- batch status
.venv/bin/python scripts/local_postgres.py xhs -- batch pause --batch 批次ID
.venv/bin/python scripts/local_postgres.py xhs -- batch resume --batch 批次ID
.venv/bin/python scripts/local_postgres.py xhs -- batch export --batch 批次ID \
  --format bundle --output var/exports/新的批次导出目录
```

## 工程范围

批次及有序子任务在同一 PostgreSQL 事务中创建，迁移 `0002` 新增 `batches` 和 `batch_items`，迁移 `0003` 新增读取恢复授权记录。原有任务、观察记录和预算保持原样。整批运行期间持有同一台手机的本机互斥锁；关键词切换也保留主动操作间隔。

当前是**单控制主机、单手机顺序执行**。以后可复用批次及任务边界增加调度；多主机租约、失效提交校验、设备控制通道和共享限流仍需在扩到 5 台前实现并验证。本次没有采购或启用额外设备。

批次软件与数据库迁移通过独立测试；多个关键词在真实手机上连续运行、暂停和恢复仍需按实际关键词执行一轮验证。单关键词成功及用户确认已留档，不把 synthetic 批次测试计作真实采集成果。
